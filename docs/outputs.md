# Outputs & Workdir Layout

All pipeline outputs are isolated in a per-run workdir. The source tree and build directories are never modified.

## Workdir Structure

```
<workdir>/
  results/
    ingest/
      metadata.tsv             # Raw Pathoplexus/NCBI/local metadata
      dated_metadata.tsv       # After date normalization
      filter_log.tsv           # Sequences excluded by QC (with reasons)
      qc_summary.tsv           # QC statistics (genome_quality, coverage, etc.)
      date_normalization.tsv   # Unparseable dates (for review)
    viralqc/
      outputs/
        results.tsv            # ViralQC output (genome_quality, clade, coverage)
    subsampled/
      metadata.tsv             # Subsampled metadata (input to phylo)
      sequences.fasta          # Subsampled sequences (input to phylo)
    alignments/
      sequences.fasta          # MAFFT alignment
    alignments/
      masked.fasta             # After terminal + BED masking
    trees/
      tree.nwk                 # Maximum-likelihood tree (Newick)
    refine/
      tree.nwk                 # Time-calibrated tree
    node_data/
      nt_muts.json             # Nucleotide mutations
      aa_muts.json             # Amino acid mutations
      traits.json              # Ancestral state (geographic, clade)
      clades.json              # Clade assignments
      branch_lengths.json      # Branch lengths (time-scaled)
  auspice/
    results.json               # Final Auspice JSON (visualization-ready)
  config/
    snakemake_resolved.yaml    # Merged config + resolved ViralQC paths
    subsample_resolved.yaml    # Resolved subsample config
    latlongs.tsv               # Geographic coordinates (Nominatim)
    colour_scheme.tsv          # Hex colors by metadata value
    name2hue.tsv               # Hue assignments for deterministic coloring
  cache/
    cache_coordinates.tsv      # Persistent coordinate cache (updated at runtime)
  logs/
    ingest.log                 # Snakemake ingest log
    phylo.log                  # Snakemake phylo log
  manifest.json                # Run provenance + config hash
  .flexpipe.lock               # Lock file (filelock, exclusive)
```

## Key Output Files

### Visualization-Ready: auspice/results.json

This is the final output for visualization. Open with:

```bash
auspice view --datasetDir <workdir>/auspice/
```

Contains:
- Tree (time-calibrated phylogeny)
- Metadata (strain, date, region, etc.)
- Node data (mutations, traits, clades)
- Color scheme
- Auspice configuration (filters, panels, geo resolutions)

### Quality Control: results/ingest/qc_summary.tsv

Tab-separated summary of QC statistics:

| Column | Purpose |
|--------|---------|
| `attribute` | QC metric name |
| `value` | Value or count |

Example rows:
- `input_sequences`: 500
- `sequences_after_qc`: 450
- `min_coverage_filter`: 20
- `genome_quality_a_count`: 300
- `genome_quality_b_count`: 150

### Subsampled Metadata: results/subsampled/metadata.tsv

Filtered and subsampled metadata (input to phylogenetics). Columns include:

- Pandoc Pathoplexus fields: strain, country, division, location, date, etc.
- Enriched fields: region (continent or Brazilian macro-region), clade_truncated, lineage (parsed), source
- ViralQC results: genome_quality, coverage

### Filter Log: results/ingest/filter_log.tsv

Tab-separated log of excluded sequences:

| Column | Purpose |
|--------|---------|
| `strain` | Sequence ID |
| `filter_value` | Filter that excluded it |
| `filter_type` | Type (e.g., `genome_quality`, `min_coverage`) |

### Manifest: manifest.json

Run provenance and configuration fingerprint:

```json
{
  "workflow": "flexpipe",
  "version": "0.2.0",
  "run_id": "abc123def456",
  "config_hash": "sha256-...",
  "workdir": "/tmp/yfv-run",
  "build_config_path": "builds/yfv-brazil/config.yaml",
  "data_source": "pathoplexus",
  "timestamp": "2026-01-15T12:30:00Z",
  "run_date": "2026-01-01",
  "stages_completed": ["ingest", "phylo"]
}
```

**Uses**:
- `config_hash`: verify that two runs used identical config (deterministic reproducibility)
- `run_id`: unique run identifier (e.g., for batch tracking)
- `stages_completed`: check which stages finished

### Lock File: .flexpipe.lock

Binary lock file created by `flexpipe-run`. Prevents simultaneous runs on the same workdir.

If a run crashes, the lock may persist. To clear it:

```bash
rm <workdir>/.flexpipe.lock
```

## Config Snapshots

### snakemake_resolved.yaml

**Workdir**: `<workdir>/config/snakemake_resolved.yaml`

Complete merged configuration passed to Snakemake:
- Original build config + pydantic-resolved overrides
- ViralQC paths (conda env, datasets_dir, executable, etc.)
- All key-value pairs needed by Snakefile rules

Generated by `flexpipe-run` before invoking Snakemake. Read-only after generation.

### subsample_resolved.yaml

**Workdir**: `<workdir>/config/subsample_resolved.yaml`

Resolved subsample configuration with `--run-date` merged into `defaults.max_date`.

## Intermediate Outputs

These are often deleted if `parameters.keep_files: false` to save disk space:

- `results/alignments/sequences.fasta` — MAFFT alignment (can be large)
- `results/alignments/masked.fasta` — masked alignment
- `results/trees/tree.nwk` — pre-refinement tree

## Coordinate Cache

**Path**: `<workdir>/cache/cache_coordinates.tsv`

Persistent cache of geocoding results (latitude, longitude for each location string). Built up at runtime from:
1. Bundled seed cache (`flexpipe/data/geo/cache_coordinates.tsv`)
2. Build-specific cache (`builds/<name>/cache_coordinates.tsv`)
3. Nominatim API queries (1 req/sec rate-limiting)

Shared across runs via `coordinates.shared_cache` config key.

## Logs

### Snakemake Logs

- `logs/ingest.log` — ingest stage standard output
- `logs/phylo.log` — phylogenetic stage standard output

Each contains Snakemake's rule execution timeline, timing, and error messages.

### Date Normalization Log

**Path**: `results/ingest/date_normalization.tsv`

Records unparseable or ambiguous dates from curation:

| Column | Purpose |
|--------|---------|
| `strain` | Sequence ID |
| `original_date` | Value that failed to parse |
| `reason` | Parse error or ambiguity note |

Example:
```
SEQ_001	2020/01-05	Ambiguous (slash date: 2020-01-05 or 2020-05-01?)
SEQ_002	unknown	Unknown literal
SEQ_003	2020-13-01	Invalid month: 13
```

Use this file to identify problematic source dates and update `curation.date_formats` if needed.
