## Remaining Items

### Deferred from Sprints 3–4 ✅ All resolved (commit `a2a1828`)

**`--run-date` wired to Snakemake (§3.1 of baseline)**  
`run_date` is now passed as `--config run_date=<date>` to both Snakemake invocations.  
The ingest Snakefile's new `resolve_subsample_config` rule writes a workdir-local copy of
`subsample.yaml` with `defaults.max_date = run_date` injected before `augur subsample` runs —
bounding the analysis window without touching the source tree. Direct `snakemake` invocations
(no `run_date=` in `--config`) continue to work unchanged (backward-compatible).  
`_hash_config` now includes `run_date` in the SHA-256 digest so the `run_id` encodes the analysis
window; same config + same date → same hash.  
Key files: `flexpipe/config.py` (`resolve_subsample_config`), `flexpipe/run.py`
(`_run_snakemake` + `run_date` kwarg), `ingest/Snakefile` (new rule, updated `prepare`),
`flexpipe/manifest.py` (`_hash_config`). 16 new tests (unit + integration).

**Dockerfile hardened (§3.5 of baseline)**  
`.dockerignore` added — excludes `.git/`, `viralQC/`, `tests/`, `builds/`, `__pycache__/`, `*.pyc`,
review docs, and local workdir outputs. Base image pinned to `condaforge/miniforge3:26.3.2-3`
(dated tag matching `latest` as of 2026-06-03). Dockerfile now builds from `nextstrain.lock.yml`
(pinned spec) and uses `ARG FLEXPIPE_VERSION` / `ENV SETUPTOOLS_SCM_PRETEND_VERSION` so
hatch-vcs resolves a real version without `.git`. ViralQC datasets volume mount is documented in
the Dockerfile header comment.

**Dependency pinning (§3.2 of baseline)**  
Cross-platform version-only pins committed (no build strings → portable across `linux-64` /
`osx-arm64`; conda re-solves the build per architecture):
- `config/nextstrain.lock.yml` — pinned conda spec for all direct + key transitive deps
- `requirements.lock.txt` — pinned pip deps for the flexpipe package (runtime + dev/test)
Original `config/nextstrain.yml` (floor-based) preserved for flexible/dev installs.
Lock-file refresh cadence documented in `CLAUDE.md` (§ "Lock file maintenance").

**hatch-vcs versioning (§7.7 of baseline)**  
`pyproject.toml`: `dynamic = ["version"]`, `hatch-vcs` in `[build-system].requires`,
`[tool.hatch.version] source = "vcs"`. `flexpipe/__init__.py` now uses
`importlib.metadata.version("flexpipe")` (falls back to `"0.0.0+unknown"` when not installed).
CI jobs updated with `fetch-depth: 0` so tag history is available during `pip install`.
Git tag `v0.2.0` created; `flexpipe.__version__` resolves to `"0.2.0"` after reinstall.

## Sprint 5 — Scientific Depth and Generalization (Next)

These items were explicitly deferred to Sprint 5 in the baseline roadmap. None have been touched.

### 5.1 No minimum-sequences guardrail (§5.4 of baseline)
Nothing stops the pipeline from building a timetree from 5 sequences. A dataset too small for a
meaningful phylogeny proceeds silently through IQ-TREE and TreeTime.  
**Suggested fix:** Add `min_sequences: 10` config key (default) and check it in `validate_boundary`
(or a preflight step in `run.py`) before alignment, exiting with a clear message if not met.

### 5.2 No temporal-signal diagnostic before timetree (§5.1 of baseline)
The pipeline goes directly from the phylogenetic tree to TreeTime with no root-to-tip regression
or clock-rate check. For a new pathogen with poor temporal signal, the timetree is produced but
may be meaningless.  
**Suggested fix:** Add an optional `clock_filter` rule running `treetime clock` that exports a
root-to-tip plot and clock-rate estimate to `<workdir>/results/clock_report.json`, with a
configurable R² warning threshold.

### 5.3 No per-run QC summary artifact (§4.4 of baseline)
There is no human-readable QC report persisted as an artifact: no per-filter drop counts, no
genome-quality distribution, no geocoding miss-list, no excluded-sequences list with reasons.
An operator cannot audit a run's data quality without reading logs.  
**Suggested fix:** Write a `<workdir>/results/qc_summary.tsv` (or `qc_report.json`) after the
`curate_qc` step with sequence counts per quality grade and exclusion reasons.

### 5.4 Second build and generalization proof (§6.1 of baseline)
The pipeline's claim to pathogen-agnosticism is untested beyond YFV-Brazil. The README references
`builds/rsv-global/` which does not exist. The config-override wiring fixed in Sprint 1 has never
been exercised end-to-end.  
**Suggested fix:** Add `builds/example-global/` with a minimal NCBI-source, country-region config
(RSV or a comparable organism). This would prove the generalization architecture and give CI's
integration test a second real target.

### 5.5 Multi-build orchestration and workdir locking (§3.4 of baseline)
`flexpipe-run` is single-build. Multi-build operation requires an external loop. `--nolock` is
still passed to Snakemake, meaning two concurrent runs of the same workdir will corrupt each other.  
**Suggested fix (minimal):** Replace `--nolock` with a workdir-level `filelock` in `run.py`.  
**Suggested fix (full):** A `builds_registry.yaml` + `flexpipe-scheduler` entry point that
iterates builds, checks `config_hash` for changes, and invokes `flexpipe-run` with locking and
exit-code reporting.

### 5.6 Segmented-virus support documented as out-of-scope (§6.2 of baseline)
The ViralQC join supports `expected_segment` flagging but the rest of the pipeline (single
reference, single alignment, single tree) has no per-segment fan-out. This gap is not documented.  
**Suggested fix:** Add a note to `CLAUDE.md` and `README.md` explicitly marking segmented-virus
support as out-of-scope for v0.x.

### 5.7 Masking is positional and per-reference (§5.3 of baseline)
`mask_5prime: 142` and `mask_3prime: 548` are tuned to YFV reference X03700.1. `mask_sites: "1"`
adds nothing (already covered by the 5′ trim). No support for a problematic-sites BED file.  
**Suggested fix:** Document that positional values must be updated per-reference. Add a
`mask_sites_file` config key accepting a BED file path.
